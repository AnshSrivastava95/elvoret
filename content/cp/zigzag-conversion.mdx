# Zigzag Conversion

## The Problem

You are given a string `s` and an integer `numRows`.

Write the characters of the string in a zigzag pattern across `numRows` rows and then read the rows from top to bottom.

For example:

```text
Input:
PAYPALISHIRING
3
```

The characters are arranged like this:

```text
P   A   H   N
A P L S I I G
Y   I   R
```

Reading the rows from top to bottom gives:

```text
PAHNAPLSIIGYIR
```

The important thing to understand is that the spaces shown above are **not part of the string**.

They only help us visualize the zigzag.

Don't immediately think about the final optimized code.

Start by asking:

> **How would I physically arrange these characters into rows?**

Then ask:

> **Do I actually need to build the entire visual matrix?**

That second question is where the problem becomes much simpler.

## The Important Observation

For:

```text

numRows = 3
```

the row numbers follow this pattern:

```text
0 → 1 → 2 → 1 → 0 → 1 → 2 → 1 → 0 → ...
```

This is the actual zigzag movement.

The characters are simply assigned according to this sequence.

So instead of constructing:

```text
P   A   H   N
```

I can think:

```text
P → row 0
A → row 1
Y → row 2
P → row 1
A → row 0
L → row 1
I → row 2

```

Now the problem becomes a simple simulation problem.

## Do We Need a Matrix?

No.

This was one of the most important realizations for this problem.

We don't need to know:

```text
which column?
how many spaces?
where is the diagonal?
```

We only need to know:

```text
which row?
```

So instead of a 2D matrix, we can create one string for every row:

```cpp
vector<string> rows(numRows);
```

If:

```cpp
numRows = 3;
```

then we have:

```text
rows[0] → ""
rows[1] → ""
rows[2] → ""
```

Think of each string as a bucket.

```text
Row 0 → characters belonging to row 0
Row 1 → characters belonging to row 1
Row 2 → characters belonging to row 2
```

We don't need to preserve the physical spaces of the zigzag.

## The Real Problem: How Do We Move Between Rows?

Now we need to simulate this:

```text
0 → 1 → 2 → 1 → 0 → 1 → 2 → 1 → ...
```

We need two pieces of information:

```cpp
int row = 0;
int direction = 1;
```

`row` tells us where we currently are.

`direction` tells us where we are going.

We use:

```text
direction = 1   → move down
direction = -1  → move up
```

So:

```cpp
row += direction;
```

means:

> Move one row in the current direction.

---

## Understanding Direction

This is the most important part of the solution.

Suppose we have three rows:

```text
0
1
2
```

We start at:

```text
row = 0
direction = 1
```

So we move down:

```text
0 → 1 → 2
```

But we cannot go below row `2`.

Therefore, when we reach the bottom:

```cpp
if (row == numRows - 1) {
    direction = -1;
}
```

Now we're moving upward:

```text
2 → 1 → 0
```

But we cannot go above row `0`.

So when we reach the top:

```cpp
if (row == 0) {
    direction = 1;
}
```

Now we move down again:

```text
0 → 1 → 2
```

This creates the complete movement:

```text
0 → 1 → 2 → 1 → 0 → 1 → 2 → 1 → ...
```

That is the zigzag.

## Why `numRows - 1`?

This is an important C++ indexing detail.

If:

```text
numRows = 3
```

the valid indexes are:

```text
0
1
2
```

The last row is therefore:

```cpp
numRows - 1
```

because:

```text
3 - 1 = 2
```

So:

```cpp
row == numRows - 1
```

means:

> We have reached the bottom row.

## The Row Movement

For the complete string, the row sequence is:

```text
Character: P A Y P A L I S H I R I N G
Row:       0 1 2 1 0 1 2 1 0 1 2 1 0 1
```

So at the end:

```text
rows[0] = "PAHN"
rows[1] = "APLSIIG"
rows[2] = "YIR"
```

Notice something important.

We never stored any spaces.

We never created a diagonal.

We never calculated columns.

We simply tracked the current row.

---

## Reading the Rows

The final answer requires reading the rows from top to bottom.

So we have:

```text
Row 0 → PAHN
Row 1 → APLSIIG
Row 2 → YIR
```

Concatenating them:

```text
PAHN + APLSIIG + YIR
```

gives:

```text
PAHNAPLSIIGYIR
```

That's our answer.

---

## Step-by-Step Algorithm

The complete algorithm is:

1. Handle the cases where no zigzag is necessary.
2. Create `numRows` strings.
3. Start at row `0`.
4. Start by moving downward.
5. Process every character in the string.
6. Add the current character to the current row.
7. If we reach row `0`, make the direction downward.
8. If we reach row `numRows - 1`, make the direction upward.
9. Move to the next row using `row += direction`.
10. After processing the entire string, concatenate all rows.
11. Return the result.

## C++ Solution

```cpp
class Solution {
public:
    string convert(string s, int numRows) {

        if (numRows == 1 || numRows >= s.length()) {
            return s;
        }

        vector<string> rows(numRows);

        int row = 0;
        int direction = 1;

        for (char c : s) {
            rows[row] += c;

            if (row == 0) {
                direction = 1;
            }
            else if (row == numRows - 1) {
                direction = -1;
            }

            row += direction;
        }

        string result = "";

        for (string r : rows) {
            result += r;
        }

        return result;
    }
};
```

## Why My First Attempt Had a Bug

A common mistake is writing:

```cpp
vector<string> rows;
```

This creates an **empty vector**.

It does not create `numRows` strings.

So if we immediately write:

```cpp
rows[row] += c;
```

we're trying to access an element that doesn't exist.

The correct version is:

```cpp
vector<string> rows(numRows);
```

Now the vector already contains:

```text
numRows empty strings
```

This is an important distinction in C++.

```cpp
vector<string> rows;
```

means:

> Create an empty vector.

While:

```cpp
vector<string> rows(numRows);
```

means:

> Create a vector containing `numRows` default-initialized strings.

---

## Why We Don't Need a Matrix

A matrix would try to preserve the visual layout:

```text
P . . A . . H . . N
A P L S I I G
Y . . I . . R
```

But those empty positions don't contribute anything to the answer.

The final answer only needs:

```text
PAHN
APLSIIG
YIR
```

Therefore, storing the characters row by row is enough.

This is an example of simplifying a problem by storing **only the information that actually matters**.

---

## Why Direction Is Better Than Manually Handling the Zigzag

We could try to write separate logic for:

```text
moving down
moving diagonally
moving up
moving diagonally
```

But that would make the implementation unnecessarily complicated.

Instead, we reduce the movement to one variable:

```cpp
int direction;
```

with only two possible states:

```text
1  → down
-1 → up
```

Then:

```cpp
row += direction;
```

handles the movement.

The boundaries decide when the direction changes.

```text
Top
 ↓
 ↓
Bottom
 ↑
 ↑
Top
 ↓
```

This is much easier to reason about.

## Complexity

Let `n` be the length of the string.

### Time Complexity

```text
O(n)
```

Every character is processed once.

After that, we concatenate the rows, which together contain exactly `n` characters.

So the overall work is linear.

### Space Complexity

```text
O(n)
```

Every character is stored in one of the row strings.

We also use the `rows` vector itself, but the dominant extra space is the `n` characters being stored.

## The Pattern

This is fundamentally a **simulation** problem.

The important pattern is:

```text
Current position
       ↓
Current direction
       ↓
Move
       ↓
Hit boundary?
   ↙          ↘
 yes          no
  ↓            ↓
reverse      continue
direction
```

The general technique is useful whenever something moves back and forth between boundaries.

The key idea is:

> **Instead of constructing the entire visual structure, simulate the movement that produces it.**
