# Two Sum

## The Problem

You are given an array of integers `nums` and an integer `target`.

Find two different elements in the array whose values add up to `target`, and return their indices.

You may assume that exactly one valid answer exists.

### Example 1

```text
Input:
nums = [2, 7, 11, 15]
target = 9

Output:
[0, 1]
```

Because:

```text
2 + 7 = 9
```

### Example 2

```text
Input:
nums = [3, 2, 4]
target = 6

Output:
[1, 2]
```

Because:

```text
2 + 4 = 6
```

### Example 3

```text
Input:
nums = [3, 3]
target = 6

Output:
[0, 1]
```

## My First Thought

My first instinct with this problem is the brute-force solution.

And that's actually a perfectly reasonable place to start.

We need to find two numbers whose sum equals the target.

So the most straightforward idea is:

1. Pick a number.
2. Compare it with every number after it.
3. Check whether their sum equals the target.
4. Continue until we find the answer.

For example:

```text
[2, 7, 11, 15]
```

We could start with `2`:

```text
2 + 7
2 + 11
2 + 15
```

Then move to `7`:

```text
7 + 11
7 + 15
```

It works.

But there is something bothering me about this approach.

We're repeatedly searching through values that we've already passed.

That feels unnecessary.

---

## Where the Problem Gets Interesting

Suppose we're currently looking at:

```text
nums[i] = 7
```

and the target is:

```text
9
```

What number do we actually need?

We can calculate it:

```text
9 - 7 = 2
```

So instead of asking:

> "Which number should I pair with 7?"

we can ask:

> **"Have I already seen 2?"**

That is a much better question.

And this is the key observation behind the optimized solution.

---

## The Important Shift in Thinking

The brute-force solution asks:

> **Which other number should I try?**

The optimized solution asks:

> **What number do I need, and have I already seen it?**

We don't need to repeatedly search the array.

We only need a way to remember the values we've already encountered.

This is exactly where a **hash map** becomes useful.

---

## The Hash Map Approach

We'll maintain a hash map containing:

```text
number → index
```

Let's walk through:

```text
nums = [2, 7, 11, 15]
target = 9
```

### Step 1 — We See 2

Current value:

```text
2
```

Calculate the complement:

```text
9 - 2 = 7
```

Have we seen `7`?

No.

So we remember `2`:

```text
2 → 0
```

### Step 2 — We See 7

Current value:

```text
7
```

Calculate:

```text
9 - 7 = 2
```

Have we seen `2`?

Yes.

Our map tells us:

```text
2 → 0
```

The current index is `1`, so:

```text
[0, 1]
```

is our answer.

---

## Why This Works

For every number:

```text
complement = target - current
```

Then we ask:

```text
Does the complement already exist?
```

If it does, we found our pair.

If it doesn't, we store the current number and continue.

The algorithm becomes:

```text
current number
      ↓
calculate complement
      ↓
have we seen it?
   ↙          ↘
 yes           no
  ↓             ↓
answer       remember
```

---

## Why Brute Force Isn't Enough

The brute-force solution checks every possible pair.

For `n` elements, the number of comparisons grows quadratically.

Therefore its time complexity is:

```text
O(n²)
```

The hash map approach makes a single pass through the array while performing fast lookups:

```text
O(n)
```

average time complexity.

We're using extra memory to achieve that improvement.

---

## The Pattern

This is a classic **Hash Map** pattern.

Whenever you're processing data and repeatedly asking:

> "Have I already seen this?"

you should start thinking about a hash map or hash set.

The underlying idea is:

> **Store useful information now so you don't have to search for it again later.**

---

## Step-by-Step Algorithm

1. Create a hash map storing `number → index`.
2. Traverse the array from left to right.
3. Calculate `complement = target - current`.
4. Check whether the complement already exists.
5. If it exists, return its index and the current index.
6. Otherwise, store the current number and continue.

---

## C++ Solution

```cpp
#include <vector>
#include <unordered_map>

using namespace std;

vector<int> twoSum(vector<int>& nums, int target) {
    unordered_map<int, int> seen;

    for (int i = 0; i < nums.size(); i++) {
        int complement = target - nums[i];

        if (seen.find(complement) != seen.end()) {
            return {
                seen[complement],
                i
            };
        }

        seen[nums[i]] = i;
    }

    return {};
}
```

---

## Walking Through the Code

First, we create the hash map:

```cpp
unordered_map<int, int> seen;
```

We're storing:

```text
number → index
```

Then we iterate through the array:

```cpp
for (int i = 0; i < nums.size(); i++)
```

For every number, calculate what we need:

```cpp
int complement = target - nums[i];
```

Now check whether we've already encountered that number:

```cpp
if (seen.find(complement) != seen.end())
```

If it exists, we have our answer:

```cpp
return {
    seen[complement],
    i
};
```

Otherwise, remember the current number:

```cpp
seen[nums[i]] = i;
```

---

## Complexity

### Time Complexity

```text
O(n)
```

We traverse the array once. Hash map lookup and insertion are `O(1)` on average.

### Space Complexity

```text
O(n)
```

In the worst case, we may store almost every element in the hash map.

## Another Important Lesson

The optimized solution isn't just about knowing hash maps.

It's about changing the question.

Instead of:


we think:


```text
Have I already seen that number?
```

Good algorithms often come from asking a better question.
